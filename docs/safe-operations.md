# Безопасные операции на MikroTik / RouterOS

Этот документ — обязательная памятка перед любыми разрушительными (destructive)
действиями на роутере: `reset-configuration`, смена адресации, правка firewall,
переключение default-route, работа с контейнерами. Он написан по следам реального
инцидента (см. [разбор ниже](#разбор-инцидента)), когда factory reset был выполнен
через канал управления, который заводская конфигурация не пережила, и роутер
потерял доступность.

## Политика mikwg

Установка mikwg **не требует и не выполняет factory reset**. Ни `rscgen`, ни
сгенерированный `routeros.generated.rsc` не содержат `reset-configuration`:
скрипт идемпотентно дополняет рабочую конфигурацию. Подготовку роутера
(установка пакета `container`, `/system/device-mode/update container=yes`,
загрузка файлов, бэкап) пользователь выполняет сам по чек-листу из
[`README.md`](../README.md). Разделы ниже про `reset-configuration` оставлены
**как справочные** — на случай, если сброс понадобится по другим причинам; к
установке mikwg они не относятся.

## Правило №0

> **Никогда не выполняйте destructive-операции, пока не обеспечен гарантированный
> путь управления, который переживёт эту операцию.**

«Я прямо сейчас могу зайти» — **не** доказательство. Управление может держаться на
текущей (пользовательской) конфигурации: маршрутах, bridge, NAT, правилах firewall.
Сброс/смена конфигурации это уничтожит.

## 1. Перед любым изменением: проверьте, ОТКУДА вы управляете

Выясните, в какой подсети и на каком порту находится ваш управляющий хост
относительно роутера:

```rsc
/ip address print
/ip route print
/interface print
/interface bridge port print
```

Сопоставьте с адресом вашей рабочей станции:

```bash
# на рабочей станции
ifconfig | grep "inet "        # macOS/Linux
ipconfig                     # Windows
netstat -rn
```

Проверьте, что ваш источник попадает в `interface-list=LAN` роутера и что между
вами и роутером нет «заимствованных» маршрутов/NAT, которые исчезнут после сброса.

## 2. Используйте Safe Mode RouterOS

В интерактивном терминале (Winbox Terminal или SSH) нажмите **Ctrl-X** — включится
safe mode (приглашение станет `<SAFE>`). Если связь с роутером оборвётся до выхода
из safe mode, **все внесённые изменения автоматически откатятся**. Это лучшая
защита от блокировки при удалённой работе.

Выход из safe mode — снова **Ctrl-X** (с подтверждением), тогда изменения
фиксируются.

## 3. Back/up перед изменениями

```rsc
/system backup save name=pre-change          # бинарный бэкап (со всеми секретами)
/export file=pre-change-export               # текстовый экспорт
```

- **Скачайте бэкап к себе** — не храните единственную копию на самом устройстве.
  Работающие способы для RouterOS 7:
  - **Winbox → Files** → перетащить `*.backup` на компьютер (самый простой);
  - **FTP** (`ftp://192.168.88.1`, служба ftp включена по умолчанию);
  - SFTP (`sftp admin@192.168.88.1`) — работает, но капризен в скриптах.
  - SCP RouterOS **не поддерживает**.
- Убедитесь, что знаете, как восстановить: `/system backup load name=pre-change`
  (введёт пароль/подтверждение и перезагрузит роутер).

## 4. Сброс с гарантией доступа (run-after-reset) — справочно, вне установки mikwg

У RouterOS есть штатный механизм: сразу после сброса выполнить скрипт. Это
единственный безопасный способ делать `reset-configuration` удалённо.

1. Создайте (вручную) в Files файл `safe-reset.rsc` с содержимым ниже — в
   репозитории mikwg этого файла нет:

```rsc
# Выполняется ПОСЛЕ сброса — гарантирует доступ оператору.
/ip service enable ssh
/ip service enable winbox
/ip service enable www

# Разрешить управление с подсети оператора в начало input-цепочки.
/ip firewall filter add chain=input action=accept protocol=tcp \
    dst-port=22,8291,80 src-address=192.168.1.0/24 \
    place-before=0 comment="OOB management (temporary)"

# При необходимости — зафиксировать адрес управления на известном порту:
# /ip address add address=192.168.88.1/24 interface=bridge
```

2. Выполните сброс с этим скриптом:

```rsc
/system reset-configuration keep-users=yes run-after-reset=safe-reset.rsc
```

`keep-users=yes` сохраняет пользователей и их пароли. Убедитесь, что помните пароль
администратора; если не уверены — задайте его заранее:
`/user set admin password="..."`.

3. **После восстановления доступа удалите временное правило** и/или сам файл
   `safe-reset.rsc`, чтобы не оставлять открытое управление с WAN.

> ⚠️ Флаг `no-defaults=yes` грузит **пустую** конфигурацию, `no-defaults=no`
> (по умолчанию) — **заводскую**. Для «чистого старта по умолчанию» нужен
> `no-defaults=no`; при этом обязательно понадобится `run-after-reset` или
> физический доступ.

## 5. Если нет run-after-reset — делайте это только с физическим доступом

Если вы не можете гарантировать доступ скриптом:

- подключайте управляющий компьютер **напрямую в LAN-порт** (для hAP ax³ —
  ether2–ether5, НЕ ether1/WAN);
- имейте под рукой **Winbox в режиме MAC** (Neighbors → подключение по MAC);
- помните про кнопку **Reset** (кратковременное нажатие на включённом устройстве
  грузит заводские настройки с `admin` без пароля; Netinstall — при зажатой кнопке
  в момент включения);
- для устройств с LCD/кнопкой — следуйте подсказкам.

## 6. Меняйте по одному и проверяйте

- Не смешивайте сброс и настройку: сначала получите доступ, потом настраивайте.
- Для маршрутов/туннелей используйте **отдельную routing-table для проверки**, не
  трогая default-route:
  ```rsc
  /routing/table add name=test fib
  /ip route add dst-address=0.0.0.0/0 gateway=<tun> routing-table=test
  /ping 8.8.8.8 routing-table=test
  ```
- Переключайте дефолт только после успешного теста.
- Не оставляйте firewall без явного правила управления из LAN на время работ.

## 7. Восстановление доступа, если уже заблокировались

По порядку:

1. Подключиться к **LAN-порту** и открыть `http://192.168.88.1` / Winbox.
2. Winbox **по MAC** (L2) — если IP недоступен/изменён.
3. Если пароль утерян — **Reset** (короткое нажатие) → вход `admin` без пароля.
4. Если устройство не отвечает вообще — **Netinstall**.
5. Восстановить из бэкапа: `/system backup load name=pre-change`.

## 8. Чек-лист перед destructive-операцией

- [ ] Я знаю, из какой подсети/порта управляю (`ip address`, `route`, `bridge port`).
- [ ] Мой источник входит в `interface-list=LAN` (или я использую отдельный порт).
- [ ] Есть `run-after-reset`-скрипт **или** физический доступ к LAN-порту.
- [ ] Сделан бинарный бэкап и текстовый экспорт, бэкап **скачан** на рабочую станцию.
- [ ] Я помню пароль администратора, и `keep-users` его сохранит.
- [ ] Включён **Safe Mode** (Ctrl-X) там, где это возможно.
- [ ] После восстановления доступа временные послабления firewall будут удалены.

## Разбор инцидента

**Дано.** Роутер hAP ax³ за адресом `192.168.88.1`; управляющая станция — в сети
`192.168.1.0/24` (сторона провайдера/Beeline). Доступ к `192.168.88.1` по SSH
работал, но опирался на текущую пользовательскую конфигурацию.

**Что было сделано.** `/system reset-configuration keep-users=yes skip-backup=yes` —
factory reset без `run-after-reset` и без проверки топологии.

**Почему потеряли доступ.**
1. Управление шло не из LAN-подсети. Заводской firewall `drop all not coming from
   LAN` блокирует вход с WAN-стороны (`192.168.1.x`).
2. Сброс убрал кастомные маршруты/NAT/bridge, на которых держался путь к
   `192.168.88.1` с рабочей станции.
3. Не было гарантированного out-of-band доступа (run-after-reset/физический порт).

**Чему учит.** Девайс при этом, скорее всего, исправен — недоступность была вызвана
потерей канала управления, а не поломкой. Правила №0, §1, §4 и чек-лист §8
предотвращают этот сценарий.
